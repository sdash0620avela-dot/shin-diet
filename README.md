# AI Life Navi（筋トレ専用AIパーソナルトレーナー）v23

AI Dietを土台に、筋トレ専用アプリへ改修（2026-11-27 仕様書に基づく）。食事などの既存データは削除せず、通常画面から外しています（記録画面のコードとデータは残存）。

## 画面
- **ホーム**：今日の部位（ローテーション 胸→背中→肩→脚→腕、前回部位から判断）、前回の日付・店舗・時間、店舗・予定時間・疲労度・痛み、［今日の筋トレを開始］。保存済み／前回実績からのメニューを即時表示し、AIは裏で調整（最大60秒、待たずに開始可）。
- **筋トレ**：全種目を縦スクロールで、セットごとに［区分（準備／本）・重量・回数・完了］。小数重量、チェック解除、セット追加・削除、種目追加・変更・削除・並べ替え、左右別、RIR・メモ。レストタイマー（自動開始・一時停止・+30秒・スキップ、実時刻で再計算）。操作ごとに端末へ即時保存、クラウドへ非同期同期。
- **終了**：未完了セットは実績に含めず確認。連打・再試行で重複登録しない。時間・総/準備/本セット・総/本レップ・疲労度・痛み・推定活動消費kcal（MET×3.5×体重÷200×分 − 安静時、推定値）をプログラムで計算。前回比較（同店舗・同機器、ダンベルは店舗共通、共通する最大重量の回数）、AI評価、次回目標。次回メニューを事前生成（次の部位×両店舗、今回部位×両店舗）。
- **履歴**：店舗・部位・期間・種目名で検索、全セット表示、種目別推移、部位別週間セット数、時間・疲労度、体重・体組成。ChatGPTで確定した11/24〜26の実績を固定IDで登録（重複防止・登録前バックアップ）。
- **AIコーチ**：「今日、塩田」（前回部位から次の部位を判断し準備）、「肩が少し痛い」「ケーブルが空いてない」「今日は45分しかない」→変更案を表示し**承認後に**反映（完了済みセットは変更しない）。「〜の方が効く」→種目評価として保存。「前回より伸びてる？」→同店舗・同機器で数値比較。
- **設定**：本人のプロフィール（年齢・身長・目標・頻度・ローテーション・時間・セット数・既往・除外種目・タイマー）、種目評価（効き方／痛み／好み／設備／優先度）、店舗設備、AIへの指示。

## 判断の仕組み
- プログラム（`workout-engine.js`）：全履歴の抽出（v23セット単位・旧形式・自由記述・取り込み）、重量方式（ダンベル片手・店舗共通／マシン・ケーブル・プレート式は店舗・機器別、似た名前の別機器を統合しない）、同部位の直近セッションを土台にしたセット単位の計画（本人の準備セットを引き継ぎ、本セットは一部だけ漸進）、除外・設備・代替、痛み・疲労、時間配分、動線（同器具連続・ケーブル/ダンベルまとめ・塩田店ケーブル15分）、AI出力の検証。
- AI（Worker `workout_plan`／`workout_chat`／`workout_review`、構造化出力strict）：仕様書6-2の判断順序、本人プロフィール・種目評価・店舗設備・全履歴の構造化要約・検証済み科学的根拠を参照。

## v22.0 筋トレAIコーチ（AI Life Navi 筋トレ機能）

下部タブ「筋トレ」から、店舗（本店・塩田店）と部位を選ぶだけで、その場でメニューが表示され、すぐ開始できます。

### v22.4（「75分なのに48分」「重量が空欄」「プロンプトが使われていない」）
- 指定時間を使い切る：種目数の上限を7（全身8）に上げ、余った時間は主要種目からセットを追加（1種目5セットまで）。AIにも指定時間を使い切るよう指示。
- プロンプト利用時の仮メニューは重量を空欄にせず、他の記録の前回値を入れる。
- AI作成の依頼が画面の再描画で取り消され、「作成中」のまま届かないことがあった不具合を修正。待ち時間の上限を90秒にし、経過秒数を表示。プロンプト利用時は応答を速くする設定。

### v22.3 プロンプト優先（「プロンプトを守ってほしい」「余計な表示はいらない」）
- コーチのプロンプトを保存すると、それをAIの**最優先の指示**にする。アプリ独自の判断ルール（設備未確認・他店重量の禁止・+10%上限・基準案）は使わず、出力形式・根拠のない重量はnull・強い痛みの除外だけを残す。アプリ側の補正もしない。
- 重量が書かれていないルールだけのプロンプトも保存し、すぐ作り直す。
- 画面を簡素化：選択1行・メニュー・コーチに伝える・開始のみ。プロンプト・種目追加・記録・設定は「その他」に格納。注意は最大2件・折りたたみ。
- 不具合修正：AIの結果で画面が更新されると「コーチに伝える」の入力途中の文字が消えていた。
- 取り込み時は本人の書いた種目名をそのまま使う。ルール文（例「前回全セット12回できたら2.5kg上げる」）を種目と誤認しない。

### v22.2 で直したこと（「背中の追加候補がない」「前のコーチのプロンプトを貼りたい」「開始時に重量が入っていてほしい」）
- 「📋 前のコーチのメニューを貼り付け」を追加。「コーチに伝える」に貼った場合も自動で取り込み。AI（Worker `workout_import`、構造化出力）で読み取り、不通時は端末内で読み取り。
- 取り込んだ種目・重量・回数・セットは店舗・部位ごとの次回メニューになり、「筋トレ開始」で重量が入った状態で始まる。以後の自動メニューの重量基準にもなる（同じ店舗のみ）。方針（避ける種目・痛みなど）は恒久設定とAIへの方針メモに保存。取り込みは取り消し可能。
- 種目カタログを拡充（背中は15種目など）。一覧にない種目名の入力欄を常時表示。

### v22.1 で直したこと（利用者の指摘：「実績が反映されない・追加がわからない・何が変わったかわからない」）
- v21.1より前の**自由記述の筋トレ記録**（例「胸25セット　1時間」「チェストプレス50kg×10×3」）も読み取り、部位の間隔・週セット数・重量に反映。
- 店舗名が本店・塩田店と判別できない記録は件数を表示し、ワンタップで「本店として扱う／塩田店として扱う」を選べる（元の記録は変更しない）。
- 各種目に「前回 日付：重量×回数」を表示。「これまでの筋トレ記録」で読み取った記録の内訳と直近10回を表示。
- 「＋ 種目を追加」（計画中・実施中どちらでも）。初回のみ「新しくなりました」の4ステップ案内。
- 店舗・部位・時間の選択を1行に折りたたみ、最初の画面からメニューが見えるように変更。

### 設計の要点
- **AIを待たない構成**：`workout-engine.js` が全履歴を端末内で分析し、即時に計画を作成（オフライン可）。ログイン・送信同意済みなら、裏でAI（Worker `workout_plan`）が全履歴要約・痛み・店舗設備・科学的根拠を統合して最適化し、届いたら差し替え・保存。AIが遅い・失敗しても開始できる。
- **AI出力の検証**：構造化出力（JSON Schema strict）をアプリ側で再検証。同店舗の実績がない重量は採用しない、前回比+10%超の増量は補正、恒久設定で除外した種目は削除。
- **店舗別**：重量は「同じ店舗・同じ種目」の実績からのみ設計。他店舗の重量は「参考」表示のみ。
- **自動保存と復元**：開始時刻・重量・回数・完了チェックは入力ごとに端末へ即時保存、4秒ごとにクラウド設定へミラー。再読み込み・アプリ終了・オフライン起動・別端末でも復元。
- **終了後**：セット単位の実績を日別記録（`workoutSessions`）と従来項目（`workoutExercises` 等）の両方へ保存し、次回の部位を決めて次回メニューを生成・保存。ホームに即時表示。
- **会話**：「塩田店にはペックフライがない」「今後スクワットは外して」等を Worker `workout_chat` で解釈し、今日のメニューと恒久設定（`settings.workoutCoach.prefs`）を更新。AI不通時は端末内の簡易解析で処理。
- **科学的根拠**：`science/evidence.json`（PubMedで原典照合済みのみ `verified:true`）をAIの判断ルールと画面の根拠表示に使用。`scripts/collect-science.mjs` と月次ワークフローが新しい系統的レビュー・メタ解析を収集し、原典検証待ちのIssueを作成（検証前は反映しない）。

### データ（既存データは変更しない）
- 日別記録 `diet_records.record`：既存項目はそのまま。筋トレ実績は `workoutSessions`（追加項目）と従来項目に保存。
- 設定 `diet_profiles.settings.workoutCoach`：恒久設定・保存済み計画・実施中セッション・次回予定。
- テーブル・RLSの変更なし（SQLの再実行は不要）。

### モデル
- 既定：`gpt-5.4-mini` → 失敗時 `gpt-5-mini`。Worker環境変数 `WORKOUT_AI_MODEL` を設定すると筋トレ機能だけ別モデルを優先できる（コード変更不要）。

### テスト
- `npm test`：単体・Worker（OpenAI/Supabaseはモック）。
- `npm run e2e`：iPhone 13相当のChromiumで、両店舗×全部位の生成、開始、入力、保存、再読み込み復元、オフライン、AI遅延・エラー・残高不足、履歴なし、店舗変更、会話、別端末復元、オフライン再起動を検証。Supabaseは `e2e/fake-supabase.js`（仮想クラウド）、AIはモックで、本番データには接続しない（本番Supabaseへの通信は遮断）。
